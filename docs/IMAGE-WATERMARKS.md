# Водяні знаки донорів на фото товарів

Донори підписують свої фото. Скрипти нижче показують, де саме стоїть знак, скільки фото він зачіпає, і підставляють чисте фото там, де воно є.

> Стирання самого підпису з файлів — окремий скрипт, `npm run img:dewatermark`, див. **[docs/IMAGE-DEWATERMARK.md](IMAGE-DEWATERMARK.md)**.
> Ці два шляхи не конфліктують: `img:cleanup` лише переставляє фото товару, файлів не чіпає.

| Донор | Знак | Де |
|-------|------|-----|
| **et-market** | «ЭТМАРКЕТ» | вгорі зліва, по центру, внизу справа — на конкретному фото буває не всюди |
| **vsesezon** (Prom) | «vsesezon.com.ua» | внизу по центру, на **всіх** фото |
| **in-heat** | немає | — |

## Як шукається знак

Ручних шаблонів немає: знак знаходиться сам.

1. Фото одного донора й **однакового розміру** групуються (знак накладається в пікселях, тож на фото іншого розміру він в іншому місці).
2. По групі усереднюється поле градієнтів. Різний вміст гаситься, спільний накладений знак — ні (ідея [Dekel et al., CVPR 2017](https://openaccess.thecvf.com/content_cvpr_2017/papers/Dekel_On_the_Effectiveness_CVPR_2017_paper.pdf)).
3. Сильні пікселі середнього поля дають **маску** знака; вона розбивається на **зв'язні зони** — по одній на кожне місце, де донор ставить знак.
4. Оцінка фото — нормована кореляція його градієнтів із шаблоном, **окремо по кожній зоні, береться найкраща**. Інакше знак, присутній лише в одному місці, «розбавився» б порожніми зонами.

Шаблон приймається, лише якщо помітна частка фото групи збігається з ним **майже точно** (`≥ 0.9` у ≥ 20 % фото). Без цієї перевірки за знак береться спільна композиція фото — наприклад, сотня схожих кабелів в one й тій самій рамці.

Пороги міняються змінними: `IMAGE_WATERMARK_THRESHOLD` (0.15), `IMAGE_STRONG_MATCH` (0.9), `IMAGE_MIN_STRONG_SHARE` (0.2), `IMAGE_MIN_TEMPLATE_PHOTOS` (40), `IMAGE_SAME_PHOTO_DISTANCE` (6).

## Аналіз

```bash
npm run img:analyze -- --manifests --out out/images.json   # локально: data/scrape + storage/media, без БД
npm run img:analyze -- --out out/images.json               # по БД; фото з MEDIA_ROOT або MEDIA_BASE_URL
```

Нічого не змінює. У звіті: розміри й різкість по донорах, зона знака й частка фото зі знаком, однакові знімки в різних донорів (perceptual hash), і скільки товарів мають хоч одне чисте фото.

Фото беруться з `MEDIA_ROOT`, навіть якщо в БД ще зовнішній URL: mirror називає файл `sha256(URL)`, тож локальна копія знаходиться без мережі.

## Застосування

```bash
npm run img:cleanup -- --from out/images.json            # лише показати план
npm run img:cleanup -- --from out/images.json --apply
```

Потрібен звіт, зроблений **по БД** (не `--manifests`): id фото з манифестів несправжні.

Що робить:
- фото **без знака стає обкладинкою** товару, решта зсувається нижче (`sort_order`);
- фото зі знаком **замінюється на той самий знімок** із чистого джерела, якщо такий знайшовся за pHash.

Файли на диску не чіпаються, походження лишається в `source_url` — будь-яку зміну відкочує повторний імпорт.

## Що показав каталог

|---|---|---|
| et-market | 2730 | 1984 (73 %) |
| in-heat | 688 | 0 |
| vsesezon | 132 | 132 (100 %) |

З 3868 товарів: **1449** мають усі фото чисті, **368** мають і чисті, і зі знаком (досить змінити обкладинку), **2051** мають лише фото зі знаком.

**Заміна з іншого донора майже не працює.** Асортименти перетинаються лише на 9 групах товарів: донори знімають ті самі товари по-своєму, тож однакових знімків між ними майже немає.

Для решти лишаються шляхи, не пов'язані зі скриптами: фото виробника (більшість товарів брендові), власна зйомка — або стирання підпису, якщо фото наші (`npm run img:dewatermark`, див. [docs/IMAGE-DEWATERMARK.md](IMAGE-DEWATERMARK.md)). Стирати чужий знак із фото без прав на них не варто: це окремо заборонено законом про авторське право, а не лише спірно.
