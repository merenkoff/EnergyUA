# Стирання підпису сайта з фото

Фото каталогу викачані з трьох наших колишніх сайтів. На двох із них стоїть накладений підпис —
назва сайта, якої на новому сайті бути не має. `npm run img:dewatermark` знаходить підпис сам
і стирає його з файлів; рядки БД не змінюються взагалі.

| Джерело | Підпис | Де стоїть | Фото зі знаком |
|---------|--------|-----------|----------------|
| **et-market** | «ЭТМАРКЕТ» | вгорі зліва, по центру, внизу справа (на конкретному фото буває не всюди) | 1984 з 2708 |
| **vsesezon** (Prom) | «vsesezon.com.ua» | великим написом по низу кадру | 50 з 50 того самого розміру |
| **in-heat** | немає | — | 0 |

## Як це працює

Ручних шаблонів немає — модель підпису будується з самих фото.

1. **Групи.** Фото одного джерела й **однакового розміру**: підпис накладено в пікселях, тож на
   фото іншого розміру він в іншому місці.
2. **Середнє поле градієнтів** по групі: вміст у кадрах різний і гаситься, накладений підпис
   однаковий і лишається (ідея [Dekel et al., CVPR 2017](https://openaccess.thecvf.com/content_cvpr_2017/papers/Dekel_On_the_Effectiveness_CVPR_2017_paper.pdf)).
3. **Когерентність** `|Σg| / Σ|g|` відокремлює підпис від спільної композиції фото: у накладеного
   знака напрямок градієнта однаковий у всіх кадрах (→ 1), у вмісту випадковий (→ ~1/√N).
   Маска = висока когерентність **і** помітна сила середнього поля.
4. **Зони.** Маска ділиться на зв'язні частини — по одній на кожне місце, де стоїть підпис.
   Зона має бути схожа на напис: не тонша за кілька пікселів, компактна, щільно заповнена
   (так відсіюються однакові в усіх кадрах рамки й краї).

Чи є підпис на конкретному фото, вирішує **проєкція** його градієнтів на шаблон
`r = Σ(g·t) / Σ|t|²` — на відміну від косинуса, вона не залежить від того, наскільки насичений
кадр: на порожньому й на щільному фото однаковий підпис дає однакове `r`.

Кожна зона приміряється **зі зсувом до 5 px** (`IMAGE_WM_SHIFT`): підпис у донора стоїть не
піксель у піксель, а гуляє на кілька пікселів, усереднений шаблон сідає туди, де знак у більшості.
Без пошуку зсуву десята частина фото (≈300 з 2708 в et-market) лишалася б із написом — шаблон
від нього просто промахується.

### Чому зона може не пройти перевірку

Шаблон, побудований по групі схожих фото, ловить не лише підпис. Зона лишається, лише якщо
виконано все:

- **збіг у зоні** (медіанний косинус по фото, де зона спрацювала) ≥ `0.6` — накладений підпис
  збігається з шаблоном майже піксель у піксель;
- **збіг поза зоною** менший щонайменше на `0.3` — інакше це просто кілька майже однакових фото,
  які збігаються скрізь;
- зону видно **щонайменше на 20 різних товарах** — значок на самому товарі (Wi-Fi, Google Play)
  теж стоїть у тому самому місці й теж ідеально збігається, але лише в кількох товарів;
- підпис знайдено **щонайменше на половині фото групи**.

На нашому каталозі це відкидає всі групи in-heat (там підпису немає) і лишає et-market і vsesezon.

### Скільки кіл

Підпис у донора буває не один: у et-market знайшлося два варіанти логотипа — з різним підрядковим
текстом і трохи іншим місцем. Один усереднений шаблон описує лише той, що на більшості фото, тож
після кожного кола шаблон будується заново — уже по тих фото, де знака ще не знайшли — і так поки
черговий шаблон проходить перевірки (`IMAGE_WM_ROUNDS`, типово 4 кола). У другому й наступних колах
вимога «підпис на половині фото» знімається: решта — це переважно чисті фото. Решта перевірок
лишається.

На нашому каталозі друге коло шаблона вже не дало (найкращий збіг 0.29), тож усе зняло перше.

### Як стирається

Заповненням: піраміда pull-push дає перше наближення, далі ітерації Лапласа роблять шов
непомітним. Маска розширюється на 2 px — у підпису є напівпрозорий ореол, і якщо лишити його
межею заповнення, від напису лишиться кольоровий контур.

Якщо навколо підпису **рівне тло** (а так у більшості фото: напис стоїть на білому полі),
закривається весь прямокутник зони — тоді не лишиться ні тонких ліній логотипа, ні ореолу.
Там, де під підписом сам товар, закривається лише маска.

**Що лишається.** Перевірка після прогону (шаблон по резерву оригіналів, міряємо вже почищені
файли) показала: проєкція впала з медіанних 1.36 до 0.05, жодного файла з `r ≥ 0.5`, шість — із
`r ≥ 0.35`, і в чотирьох із них стільки ж було й до стирання. Назви сайта не лишилося ніде, але
у фото другого варіанта логотипа буває видно кольоровий слід від іконки, що вилізла за межі зони.
Знизити поріг (`IMAGE_WM_DETECT=0.35`) — ловиться ще ~150 фото et-market, але серед них уже
з'являються хибні: на частині кадрів підпису немає, і заливка тільки псує фото.

**Чого зробити не можна.** Там, де підпис непрозорий і лежить на самому товарі, вміст під ним
утрачено — лишається м'яка пляма. Це видно найкраще на фото vsesezon, де напис великий і йде
через товар. Спроба замість заповнення «відняти» підпис (оцінити прозорість і відновити вміст)
дає гірший для нас результат: назва сайта лишається читабельною блідим контуром.

## Запуск

```bash
npm run img:dewatermark -- --manifests                 # звіт + зразки «до / після», нічого не змінює
npm run img:dewatermark -- --manifests --apply         # переписати файли
npm run img:dewatermark                                # те саме, але список фото з БД
npm run img:dewatermark -- --restore                   # повернути оригінали
```

Без `--apply` нічого не змінюється: у `out/dewatermark/` з'являються `report.json`, маска кожної
прийнятої моделі (`mask-*.png`) і аркуші «до / після» (`sample-*.jpg`). **Дивіться маски й зразки
перед `--apply`.**

Корисні прапорці: `--donor et_market`, `--limit N`, `--samples N`, `--out DIR`, `--band`
(запасний шаблон «нижня смуга» для Prom, типово вимкнений — див. нижче).

Оригінали копіюються в `MEDIA_ORIGINALS_ROOT` (типово `storage/media-original`), а список
оброблених файлів — у `storage/media-dewatermarked.json` (пишеться по ходу, тож обірваний прогін
не губить того, що вже зроблено). Повторний запуск такі файли не чіпає й не будує по них шаблон.

Формат і розмір файла не змінюються, прозорість зберігається. Змінюється лише вміст файла —
`url` і `source_url` у `product_images` лишаються ті самі, тож ані БД, ані посилання не зачеплені.
Але саме тому `db:repair-images` (перезавантаження зниклих файлів за `source_url`) поверне фото
з підписом — після нього прогін варто повторити.

### Змінні

| Змінна | Типово | Що робить |
|--------|--------|-----------|
| `MEDIA_ROOT` | `storage/media` | де лежать файли фото |
| `MEDIA_ORIGINALS_ROOT` | поряд, `media-original` | резерв оригіналів |
| `IMAGE_WM_BACKUP` | `yes` | `no` — не копіювати оригінал (коли на volume бракує місця) |
| `IMAGE_WM_DILATE` | `2` | на скільки пікселів розширити маску |
| `IMAGE_WM_SHIFT` | `5` | наскільки шукати зсув зони на конкретному фото |
| `IMAGE_WM_FLAT_BG` | `12` | розкид кольору, до якого тло вважається рівним |
| `IMAGE_WM_MIN_PHOTOS` | `40` | мінімум фото в групі |
| `IMAGE_WM_DETECT` | `0.5` | поріг проєкції, за яким підпис вважається знайденим |
| `IMAGE_WM_MIN_MARKED` | `0.5` | яка частка фото групи має мати підпис |
| `IMAGE_WM_COHERENCE`, `IMAGE_WM_STRENGTH` | `0.55`, `0.12` | пороги маски |
| `IMAGE_WM_JPEG_QUALITY` | `92` | якість перезапису JPEG |

## На Railway

Файли фото лежать на volume, а донорські сайти більше не відповідають, тож перекачати їх
наново не вийде — стирати підпис треба на самому volume. За це відповідає змінна:

```
DEWATERMARK_IMAGES=yes
```

`scripts/railway-entrypoint.sh` запускає `remove-image-watermarks.ts --apply` у фоні після
старту (і після mirror, якщо той увімкнений). Це разовий прапорець: після успішного прогону
його варто зняти. Повторний запуск і так безпечний — оброблені файли записані в
`media-dewatermarked.json` поряд із `MEDIA_ROOT`, тобто на тому ж volume.

## vsesezon: фото інших розмірів

Підпис Prom масштабується з шириною фото й притиснутий до низу кадру. Точну групу (50 фото
500×500) видно добре, а решта 82 фото vsesezon мають по одному-два кадри на розмір — власної
групи з них не зібрати.

Для них є запасний режим `--band`: усі фото донора приводяться до ширини 500 і від них береться
нижня смуга 140 px, шаблон будується там, а маска повертається в пікселі кожного фото. На фото
різних пропорцій напис лягає не піксель у піксель, тож шаблон виходить приблизний — тому режим
типово вимкнений. Вмикати варто, лише подивившись маску в `out/dewatermark/mask-*.png`.

Див. також `docs/IMAGE-WATERMARKS.md` — там аналіз (`npm run img:analyze`) і перестановка фото
без редагування файлів (`npm run img:cleanup`).
